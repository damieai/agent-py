# 研发运维 Agent 实施计划与实际进度

依据 master spec v1.2 与已确认的选择：Bitbucket Cloud、Jira Cloud、Jenkins、Kubernetes；研发和运维同等推进；API 模型优先；自动准备、审批合并部署；GPU 后置。

本文件同时保留完整路线和当前实现证据。**整个 B00—B12 尚未完成**。当前支持持久化仿真、只读模型调查及有界候选修复，可按运维清单采集四类企业资源。模型补丁已连接沙盒编排和人工审阅；尚未用真实模型与 Docker 完成该闭环验收，不能描述为已完成生产交付。

新增执行证据：live Worker 可对已导入的授权证据执行一次模型调查，保存上下文清单和分析产物并进入人工审阅。请求摘要绑定推理身份，校验后的决策与预算结算同事务保存，支持产物写入失败后的恢复；未知响应不重发。该路径已用模拟 HTTP 验证，尚未使用真实付费模型验收。

## 架构与核心契约

- Python 3.12、FastAPI、Pydantic、SQLAlchemy、Alembic；PostgreSQL 为生产数据库，SQLite 仅开发。
- Temporal 为唯一工作流恢复权威；API 创建任务与 Outbox 同事务，Dispatcher 使用稳定 Workflow ID。
- 任务、动作、审批、恢复状态分离；operation_id 不随 Activity 重试改变。
- 受信身份与可撤销 Grant 共同授权；生产数据库运行角色不得绕过 RLS。
- 模型只产生决策与候选动作，审批与执行在 Service 层；当前 live executor 明确拒绝外部写入。
- 仿真外部系统独立持久化回执；本地账本并不假装能兑现第三方幂等。

## API 与类型

已实现：TaskContract、Principal、ActionProposal、ApprovalDecision、EvidenceRef、ModelDecision、Operation、ContextBundle、FileEdit 和 Artifact。

已实现的 HTTP 接口：

| 接口 | 当前行为 |
|---|---|
| POST /api/v1/tasks | 幂等创建与 Outbox |
| GET /api/v1/tasks、/tasks/{id} | 鉴权列表、动作、审批和产物 |
| POST /tasks/{id}/proposals | 创建稳定候选动作及必要审批 |
| POST /tasks/{id}/cancel、/takeover | 停止后续派发，保留对账 |
| POST /approvals/{id}/decisions | 摘要绑定、期限与审批角色检查 |
| GET /operations/{id} | 动作确认及恢复状态 |
| GET /tasks/{id}/events | 带序号 SSE，续传、JWT/Grant 复核、历史缺口及终止信号 |
| GET /tasks/{id}/recording | v2 一致性审计快照下载，当前授权及修复角色复核 |
| GET /artifacts/{id} | 重新鉴权、摘要校验和安全下载 |
| POST /tasks/{id}/context/preview | 当前用户范围内只读证据预览、行号与预算 |
| POST /webhooks/connector | 签名、时间窗、Inbox 去重；通知仅触发查询 |

任务中途修订、评测/回放 HTTP API、完整 AgentRelease/Plan 类型仍待实现；目前评测和回放导出通过 CLI/库入口执行。不得把这些待实现接口写入对外承诺。

### B11 无 GPU 高级实验 — planned

实现多 Agent 专家、路由与 Test-Time Compute、程序化工具、MCP、A2A、长期记忆、时态图检索、GEPA、Best-of-N/MCTS、多模态与浏览器。

每项都必须有简单基线、相同预算对照、失败样例和独立开关；不得让实验策略修改权限或执行协议。通过质量、成本和安全门槛后才能进入稳定发布。

### B12 GPU 与训练 — planned，资源门槛独立

先实现脱敏数据导出与训练/验证/测试隔离，再分别评测 SFT、DPO、仿真内 RL 和 vLLM 推理。前缀缓存、量化、批处理与投机解码逐项比较；P/D 分离仅在瓶颈证据成立后启用。无算力时不能声称训练完成。
