# 架构与决策记录

## ADR-001：一个恢复权威

使用 Temporal 管理任务等待与重试，所有模型、工具和数据库副作用在 Activity 内。Action Ledger 保存业务动作身份与确认结果。工作流 ID 为 `agent:{tenant}:{task}`，Outbox 重试不生成第二个工作流。API 不使用进程内 BackgroundTask 承担可靠执行。

替代方案是仅使用数据库 Worker；代码保留单步仿真入口用于本地验证，但它不承担生产调度。当前未引入 LangGraph，避免两套引擎同时恢复写动作。

## ADR-002：UNKNOWN 优先于猜测失败

派发前持久化 PENDING，网络调用期间不持有数据库事务。重复进入 PENDING/UNKNOWN 不再次派发，独立 Reconciler 查询结果。权威查询未发现结果时维持 UNKNOWN；当前实现不自动原键重试，牺牲部分活性，避免误判渠道语义。派发意图持久化后、真正发送前崩溃也可能长期 UNKNOWN，需要人工处置；后续渠道级契约才能缩小该窗口。

模拟渠道在独立 SQLite 数据库原子提交副作用和回执，显式提供服务端幂等保证。这不能推广成第三方天然支持 exactly-once。

## ADR-003：权限在读取与执行层落实

身份由签名 Token 建立，项目和环境权限再查询可撤销 Grant。生产只接受外部 issuer 与 RSA 公钥；目前公钥由配置提供，尚未实现 JWKS 自动轮换。开发 Token 命令禁止在生产运行。

PostgreSQL 每事务设置可信 tenant_id，并对租户表 FORCE RLS。应用查询仍显式过滤 tenant。生产角色不得拥有表或绕过 RLS。SQLite 没有 RLS，不能替代 PostgreSQL 隔离验收。

## ADR-004：执行面默认仿真

当前提供确定性双链路模拟和独立模型分析。`live` 写执行器明确拒绝派发；启用外部写入之前必须实现对应渠道的身份、审批、提交前置条件、权威查询与竞态测试。

因此现在没有声称“自主修复代码并上线”的真实闭环。有界修复工作流已连接企业证据、源码快照、模型补丁和容器验证编排，完成后交由人工审阅；真实模型、容器隔离及企业写入仍须分别验收。

## ADR-005：本地优先，阶段性验收

SQLite + 文件产物便于启动；PostgreSQL 和 Temporal 使用真实本地服务单独测试。容器、Kubernetes、对象存储和企业连接的验证状态独立记录，不因单元测试通过而自动标为可上线。

上下文默认采用权限过滤后的词项排序；可选的 BM25/来源匹配 RRF 策略提供 Python 分块与行号追溯，使用同一编译接口进行离线消融。向量检索、GraphRAG 和动态记忆仍待实现。

## ADR-006：候选生成和验证分账

RepairRun 保存冻结输入及配置摘要，RepairAttempt 保存候选编号、补丁、验证次数和结果。模型请求使用稳定的 `repair:{run_id}:{ordinal}` 身份，复用已有推理账本；容器验证使用独立随机 token 和 CAS 领取。每轮候选都基于同一源快照，避免反馈重试时隐式修改基线。

生成次数由运维仓库绑定限定为 1—3 次。模型仅得到源码、授权证据与之前候选的结果分类，不得到 oracle 源码或原始失败日志。代价是修复反馈较粗，需要真实模型评测后再决定是否开放经过筛选的诊断信息。

验证回执落盘后、数据库结果提交前崩溃可通过 token 找回产物；没有回执的中断保持 BLOCKED，只允许 operator 显式重试同一候选，最多 3 次。新 token 防止旧执行结果覆盖新执行。成功候选只进入人工审阅，不能满足业务 SUCCESS 的独立验收要求。这不是远端写入的 fencing 保证，也不是对恶意 Python 模块的独立进程证明。

## ADR-007：数据库共享准入与分层观测

使用租户 gate 行锁串行化任务创建容量检查与执行票据领取；共享上限持久化，避免不同 Worker 配置造成并发上限漂移。执行 token 只约束本地派发，不能取消已发送的远端动作。Activity 被取消时保留租约，避免后台线程尚未结束就立即重用容量。

持久状态由数据库汇总，多副本指标按租户取 max；请求和 tick 指标为进程级累积量。用户运维视图复核当前 Grant，完整租户监控另用独立凭证和管理员白名单。trace 采用属性白名单和私密轮转文件；跨进程传播、OTLP 后端及实际告警接收人独立验收。具体边界见[运行观测](operations.md)。

## ADR-008：授权先于统计，片段绑定整篇版本

新检索策略只对可读且在有效时间内的证据计算词频、正文排名和来源排名；不可读资料不参与排名统计或遗漏清单。以纯本地算法建立可重现基线，暂不引入外部 embedding 服务与索引同步一致性问题。

片段保存整篇摘要和精确行边界，因此源文件未选中部分改变也会使上下文失效。修复快照按已记录的策略验证，保留 v1 格式兼容；默认策略变更不迁移旧推理身份。当前不缓存、不做语义压缩；模型仍引用 Document ID，片段行号服务于人工追溯。

## ADR-009：一致性审计快照与显式回放边界

审计导出使用独立只读 MVCC 快照，不通过任务行锁串行化导出与执行。PostgreSQL REPEATABLE READ、SQLite 显式读事务确保事件与动作状态来自同一视图，结束后重新检查当前授权。产物只导出摘要清单，避免把下载审计包变成隐式下载全部源码。

v2 回放以实际派发事件排序，要求租户和完整请求匹配，保留 UNKNOWN 并拒绝回放不存在的成功回执。包摘要与内部约束不证明外部状态或来源真实性，报告显式携带限制。SSE 使用相同一致性读取基础，每批重新检查 JWT 和 Grant；前端只保存有限事件并按序号恢复。

## ADR-010：读取依赖的共享熔断与代际隔离

企业 GET 可安全重复读取，但授权不能随重试复用。采集器在每次尝试前后复核任务和当前 Grant，以固定小预算重试瞬态故障，429 则共享冷却期。付费推理及外部写入保持独立执行协议，不套用读取重试。

数据库保存按租户及配置来源摘要划分的状态，行锁保证单半开探测，generation/token 拒绝旧请求关闭新熔断。人工 reset 也推进 generation。该机制不能取消在途请求，也不是依赖级 bulkhead；跨项目共享同一凭证和来源会共享熔断，需由运维统一配置与评估故障影响范围。

## ADR-011：独立信任的审计签名

用带版本和用途域隔离的 Ed25519 attestation 绑定原 v2 录制包，保持无签名格式兼容。验证方必须独立提供公钥策略、预期租户和用途；禁止包内密钥自证，禁止请求签名后静默降级。信任策略按每次验证读取，撤销覆盖历史签名，过期窗口允许历史验签。签名后仍校验业务记录结构。签名不替代不可改写存储与可信时间戳，详见[部署与限制](audit-signing.md)。

## ADR-012：数据库约束补齐租户关联

RLS 只控制行访问，不能替代引用完整性。对任务、动作、审批、产物及修复记录建立 `(tenant_id, id)` 唯一键和 13 条复合外键，即使应用层漏检查也不能提交跨租户引用。外键延迟到事务提交验证，兼容同事务多记录写入；无级联删除，保留显式数据治理边界。

迁移先检查存量数据，不静默修复。PostgreSQL 使用独立管理角色和维护窗口锁；SQLite 重建表显式包在事务内，并于提交前检查所有外键。已验证带数据升级、拒绝坏数据、失败回滚及降级再升级。此设计不证明同租户业务引用正确，也不提供不可删除存储；详见[迁移与边界](database-integrity.md)。

## ADR-013：重算证据的三态评测门禁

评测摘要分数不能独立决定通过。门禁固定数据集、算法与阈值，要求全部案例覆盖，从原始相关性标签重算检索指标，并检查配对查询退化。仿真执行协议作为硬门槛；无效或不完整报告返回证据不足，不能按零失败通过。

该实现只消费本地有界 JSON，没有 Service、网络或发布权限。CI 入口生成隔离仿真与检索证据，失败使用非零退出码；输入摘要用于复现而非来源认证。当前比较基线策略，不宣称完整 AgentRelease、代码来源证明或生产上线保障。

## ADR-014：熔断之外的共享读取容量

健康依赖也可能因大量并发请求耗尽服务容量。在原有依赖行锁内原子检查熔断与有效租约数，租户/依赖共享名额，每个逻辑读取持有唯一租约至完成或 90 秒到期。重试保留名额，重置不释放名额，重复和迟到完成不更新新状态。

本设计限制有效名额数，并不强制终止网络连接；进程暂停导致租约到期后可能仍有旧 GET 在途。调用前后验证 token 拒绝迟到结果，不为外部写入提供 fencing。容量拒绝交回持久化 Worker 等待，当前没有 FIFO 排队、跨租户供应商总配额或连接池复用。

## ADR-015：受控本地 JWKS 与严格 Token 边界

把认证信任来源固定为部署管理的本地 RSA 公钥集，令未知 kid 直接失败，拒绝 Token 指定 URL 或内嵌公钥。每次认证重新读取有界文件，支持原子替换的新旧钥重叠及删除撤钥；没有失效缓存回退，文件故障牺牲可用性以避免继续信任撤销密钥。

算法、issuer、audience、typ 由服务配置约束，JSON 与有效期独立严格校验，API 和 SSE 分页复用同一路径。共用 JSON 解析放在独立模块，避免认证与审计相互依赖。该方案不实现完整 OIDC 登录、网络发现、多副本分发或后台任务的身份撤销；这些边界及兼容变化见[认证说明](authentication.md)。
